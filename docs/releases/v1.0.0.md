The first release of Relay: a self-hostable, OpenAI-compatible LLM gateway.

## What's in it

- **OpenAI-compatible API**: `POST /v1/chat/completions` (streaming and not) and
  `GET /v1/models`. OpenAI SDKs work by changing `base_url`.
- **Providers**: OpenAI, Anthropic (Messages API, translated both ways) and a mock provider
  with configurable latency and failures.
- **Routing**: priority, weighted, cheapest and lowest-latency policies per route, with a
  per-request override.
- **Reliability**: per-attempt timeouts within a request deadline, retries with exponential
  backoff and full jitter, a circuit breaker per provider, and fallback that also works for
  streams until the first event.
- **Limits**: requests/minute, tokens/day and monthly budgets per key, enforced atomically
  in Redis (exact across replicas), with `429`, `Retry-After` and `x-ratelimit-*` headers.
- **Caching**: exact (Redis) and semantic (pgvector), tenant-isolated, with thresholds
  calibrated on a labelled set.
- **Metering**: tokens, cost and cache savings per key, route and provider in Postgres,
  daily roll-ups, and 50/80/100% budget alerts (optional webhook).
- **Admin API and dashboard** (React + TypeScript): keys, usage, provider health, alerts,
  and a "Try it" panel.
- **Observability**: Prometheus metrics, a provisioned Grafana dashboard, OpenTelemetry
  traces with a span per provider attempt, and JSON logs.
- **Operations**: Docker Compose with 3 replicas behind nginx, Alembic migrations, a
  Render blueprint for Neon + Upstash, and a container image on GHCR.

## Known limits

- One Python process per container: scale by adding replicas.
- Usage events are buffered in memory before being written in batches; a killed process
  loses at most about a second of them.
- Circuit breakers are per replica, so each replica detects a failing provider from its own
  traffic.
